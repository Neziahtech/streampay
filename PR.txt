# PR: Add `pause_stream` and `resume_stream` entrypoints

**Branch:** `feat/pause-stream-entrypoint`  
**Issue:** #1 — Add a pause_stream entrypoint  
**Difficulty:** Medium · Contract, Rust  
**Type:** feature / contract

---

## Summary

Senders can now temporarily stop accrual on a live stream without killing it (contractor on leave, audit hold). Two new sender-only entrypoints freeze accrual at the pause-time available balance and resume from the exact same point — total stream duration stretches by exactly the paused interval, so the recipient is never short-changed and the sender's unspent funds are preserved.

## What changed

### Contract (`contracts/streaming-payments/src/`)

- **`lib.rs`** — Added two entrypoints:
  - `pause_stream(env, sender, stream_id) -> Result<(), StreamError>`
  - `resume_stream(env, sender, stream_id) -> Result<(), StreamError>`
  - Both require sender authorization (`sender.require_auth()` + explicit identity check → `NotAuthorized` for third parties).
  - Both reject non-Active (Cancelled/Depleted) streams with `StreamNotActive`.
  - `pause_stream` sets status `Paused`, records `last_paused_at = now`, emits `PauseStream { stream_id, sender }` (topic).
  - `resume_stream` requires status `Paused` (else `StreamNotPaused`), computes `paused_duration = now − last_paused_at`, adds it to `paused_total`, shifts `end_time` forward by `paused_duration`, records `last_resumed_at = now`, restores status `Active`, emits `ResumeStream { stream_id, sender }` (topic).

### Contract (`contracts/streaming-payments/src/`)

- **`stream.rs`** — Stream state & pure accrual math:
  - `StreamStatus::Paused` variant added to the lifecycle enum.
  - `Stream` now persists `paused_total: u64`, `last_resumed_at: u64`, `last_paused_at: u64` (all initialized to `0` at creation).
  - `Stream::duration()` returns `end_time − start_time − paused_total`.
  - `stream_elapsed_seconds()`: while `Paused`, accrual evaluates at `last_paused_at` (frozen); while `Active`, `elapsed = now − start_time − paused_total`, clamped to `duration()`.
  - `available_amount()` zeroes for `Cancelled` streams; otherwise `streamed − withdrawn`, so withdrawals against the frozen pause-time balance remain permitted while paused.
  - `cancel_amounts()` settles the frozen accrued balance to the recipient and refunds the unaccrued remainder to the sender (works on `Paused` streams).

- **`errors.rs`** — New codes appended at the bottom (never renumbered):
  - `StreamAlreadyPaused = 18` — pause on an already-paused stream.
  - `StreamNotPaused = 19` — resume on a non-paused stream.

- **`events.rs`** — `PauseStream` and `ResumeStream` events, both keyed by `stream_id` topic with `sender` as data (wired up by the entrypoints).

## Behavior & invariants preserved

| Invariant | How it holds |
|---|---|
| `0 ≤ withdrawn ≤ streamed ≤ deposit` | Pause only pauses time; `available_amount` still caps payout at accrued-but-unwithdrawn. |
| Accrual frozen while paused | `stream_elapsed_seconds` evaluates at `last_paused_at` for `Paused` streams. |
| Duration stretches exactly by paused interval | `end_time += paused_duration` on resume; `paused_total` accumulates it; rate (`deposit / duration`) unchanged. |
| Sender-only mutating pause/resume | `require_auth()` + sender identity check. |
| Non-Active streams rejected | `StreamNotActive` for Cancelled/Depleted in both entrypoints. |
| CEI ordering | State persisted + event emitted before any token movement. |
| `paused_total` / `last_resumed_at` persisted | Stored on `Stream` so accrual math stays pure across calls. |

## Usage example

```rust
// Sender pauses a running stream for 5 days
client.pause_stream(&sender, &stream_id)?; // status = Paused, accrual frozen

// ... later, sender resumes
client.resume_stream(&sender, &stream_id)?; // status = Active, end_time += 5 days, paused_total += 5 days
```
